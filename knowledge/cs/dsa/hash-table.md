# 哈希表

## 一句话结论

哈希表用「哈希函数」把键映射到数组下标，理想情况 O(1) 读写。冲突不可避免，靠「链地址法」（同一桶挂链表/红黑树）或「开放寻址法」（线性/二次探测）解决；负载因子过高时扩容并重新哈希。

## 标准答案

**哈希函数**

把任意键（字符串、对象）映射成整数下标。好的哈希要「分布均匀、计算快、稳定」。简单的如「多项式滚动哈希」；语言内置的如 Java 的 `hashCode`、Python 的 `__hash__`。

**冲突解决：链地址法**

每个桶是一个链表（Java 8 之后链表长度超 8 转红黑树）。冲突的元素挂在同一桶下。优点：简单、删除方便；缺点：链表长时退化成 O(n)（转树后 O(log n)）。

**冲突解决：开放寻址法**

所有元素都放在数组里，冲突时就按探测序列找下一个空位（线性探测：i+1, i+2…；二次探测：i+1², i+2²…）。优点：缓存友好、无额外指针；缺点：删除麻烦（要标记墓碑）、聚集。

**扩容（rehash）**

负载因子（元素数/桶数）超过阈值（如 0.75）就扩容（通常翻倍），把所有元素重新哈希到新桶。扩容有一次性 O(n) 成本，但均摊后插入仍接近 O(1)。

## 原理展开

**为什么负载因子取 0.75 左右**

太低（桶很多）浪费内存；太高冲突增多，查找退化。0.75 是空间与时间的经验平衡点（Java HashMap 默认）。

**哈希碰撞攻击**

攻击者构造大量「哈希值相同」的键，让哈希表退化成链表，使查找变 O(n)，拖垮服务（如解析 JSON/表单时）。防御：用带随机盐的哈希（每次启动种子不同），或限制单次输入键数量。

**红黑树什么时候登场**

链地址法下，单个桶冲突过多（Java 默认链表长度 ≥8 且桶数组够大）会把该桶从链表转成红黑树，把最坏 O(n) 救回 O(log n)。这是工程上对最坏情况的兜底。

## 面试常问

1. HashMap 的 get/put 为什么是 O(1)？哈希定位桶 O(1)，桶内冲突少时链表/树很短，均摊常数。
2. 冲突了怎么办？链地址法（挂链表/树）或开放寻址（探测下一个空位）。
3. 为什么 String 适合做 key？String 不可变，哈希值算一次可缓存，且 equals 明确；可变对象做 key 改了内容就找不到了。
