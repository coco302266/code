# 文件系统：inode、目录与软硬链接

## 一句话结论

文件系统负责在存储设备上组织文件。Linux 用 inode 存文件的元数据（权限、大小、数据块指针），文件名只是目录项里指向 inode 的链接；硬链接共享同一个 inode，软链接是一个独立的特殊文件指向另一个路径。

## 标准答案

**inode 是什么**

inode（索引节点）是文件在磁盘上的元数据集合：文件类型、权限、所有者、大小、时间戳，以及指向数据块的指针。注意：**inode 里没有文件名**。文件名存在于目录项中。

**目录是什么**

目录本身也是一个文件，内容是一张「文件名 → inode 号」的映射表。所以「在目录下建文件」= 在目录文件里加一条映射；「删除文件」= 删这条映射（数据块等引用数为 0 才真释放）。

**硬链接 vs 软链接**

- 硬链接：`ln a b`，b 和 a 指向同一个 inode。删除其中一个，另一个不受影响（inode 链接数减 1，到 0 才删数据）。不能跨文件系统，不能链接目录。
- 软链接（符号链接）：`ln -s a b`，b 是一个新文件，内容里存的是「a 的路径」。a 删了 b 就失效（悬空）。可以跨文件系统、可以链接目录。

## 原理展开

**为什么删除大文件有时很快、有时很慢**

删除只是把目录项移除、inode 链接数减 1；若仍有人打开该文件（链接数未到 0），数据块不立即释放——这就是为什么「rm 了大日志但磁盘没释放」：有进程还握着文件句柄，要重启进程或清空文件（> file）才释放。

**软链接的「相对路径」坑**

创建软链接时如果填的是相对路径，它是相对于「软链接所在目录」解析的，不是相对于当前工作目录。移动软链接后容易指向错的地方而悬空。

**文件描述符 fd 和 inode 的关系**

进程打开文件时，内核用 fd 索引该进程的「打开文件表」，表里记录当前偏移量、指向 inode。多个 fd（不同进程或 dup）可以指向同一 inode。这也是「删除后仍可写入」的原理：进程握着打开文件表项。

## 面试常问

1. 硬链接和软链接区别？硬链接共享 inode（同文件多名字），软链接是独立的指向路径的文件；硬链接不能跨盘/不能链目录，软链接可以。
2. 为什么 Unix「一切皆文件」？设备、管道、socket 都抽象成可 read/write 的文件描述符，统一 I/O 接口。
3. 磁盘满了但 du 加起来没那么大？可能是删了大文件但进程仍占用（句柄未释放），或存在大量小文件把 inode 用光（df -i 看 inode）。
