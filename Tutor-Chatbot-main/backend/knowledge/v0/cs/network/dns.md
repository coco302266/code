# DNS 域名解析

## 一句话结论

DNS 把「域名」翻译成「IP 地址」。解析过程通常是「浏览器缓存 → 本地 hosts → 本地 DNS 服务器 → 根 → 顶级域 → 权威服务器」的递归/迭代查询链，结果会被多层缓存以加速。

## 标准答案

**解析过程（以 www.example.com 为例）**

1. 查本地缓存（浏览器、操作系统）：命中直接用。
2. 查 `hosts` 文件：命中直接用。
3. 发给「本地 DNS 服务器」（通常是运营商或 8.8.8.8 这类）：它代你去查。
4. 本地 DNS 问根服务器（.）：根只告诉「.com 去问 TLD 服务器」。
5. 问 TLD（.com）：TLD 告诉「example.com 去问权威服务器」。
6. 问权威服务器：返回 www.example.com 的 A 记录（IP）。
7. 本地 DNS 把结果返回浏览器并缓存。

**递归 vs 迭代**

- 递归：客户端 → 本地 DNS，本地 DNS 一查到底把结果带回（客户端只问一次）。
- 迭代：本地 DNS 自己一步步问根、TLD、权威，每一步拿「下一个该问谁」。

**常见记录类型**

- A：域名 → IPv4。
- AAAA：域名 → IPv6。
- CNAME：域名别名（指向另一个域名）。
- MX：邮件服务器。
- NS：该域名的权威 DNS。
- TXT：文本，常用于域名验证、SPF。

## 原理展开

**为什么要分层（根/TLD/权威）**

互联网域名海量，不可能一个服务器存全量。分层后每台服务器只管自己那一级，根管顶级域的位置、TLD 管二级域的位置、权威管具体记录——像查通讯录先按省再按市再按人名。

**TTL 的作用**

每条 DNS 记录带 TTL（生存时间）。缓存时间内直接用缓存，过期才重新查。TTL 短（如 60s）利于故障切换但增加查询量；TTL 长减少查询但切换慢。改 DNS 解析后生效慢，往往就是 TTL 在作怪。

**DNS 污染 / 劫持**

中间网络设备篡改或伪造 DNS 响应，把域名解析到错误 IP（常见于访问受限站点或钓鱼）。HTTPS 的证书校验能部分缓解（解析到假 IP 后证书对不上会报警）。

## 面试常问

1. 浏览器输入 URL 到显示页面经历了什么？DNS 解析 → TCP 连接 → 发 HTTP 请求 → 服务器响应 → 浏览器解析渲染（其中 DNS 是第一步）。
2. DNS 用 TCP 还是 UDP？查询通常用 UDP（快、包小），但响应超 512 字节或区域传送(AXFR)时用 TCP。
3. 什么是 CDN？内容分发网络，把资源缓存到离用户近的节点；DNS 根据用户 IP 返回最近的节点 IP，从而实现就近访问。
