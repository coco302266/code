# 进程间通信（IPC）

## 一句话结论

进程间通信（IPC）是多个进程交换数据或同步动作的机制。常见有管道、消息队列、共享内存、信号、套接字。共享内存最快（直接映射同一块内存），但需自己配锁；管道/消息队列由内核中转，简单但有拷贝开销。

## 标准答案

**管道（pipe）**

半双工（一端写一端读），通常用于有亲缘关系的进程（如父子）。匿名管道 `pipe()` 随进程消失；命名管道（FIFO）可在无亲缘关系的进程间用。数据在内核缓冲区流动，读写都经过内核。

**消息队列**

内核维护的「消息链表」，进程往队列里放带类型的消息，另一进程取。比管道灵活（可按类型取、可随机存取），但单条消息有大小上限、队列总容量有限。

**共享内存**

把同一段物理内存映射到多个进程的地址空间，进程直接读写，**最快**的 IPC（没有内核中转拷贝）。缺点：需要进程自己用信号量/锁做同步，否则会数据竞争。

**信号（signal）**

异步通知机制：`kill -9` 发 SIGKILL、Ctrl+C 发 SIGINT。信号处理函数要简短、只用异步信号安全函数，否则容易出 bug。

**套接字（socket）**

最通用的 IPC，既能本机（Unix domain socket）也能跨网络。本机 socket 比 TCP loopback 少一层协议处理，常用于同机服务间通信。

## 原理展开

**共享内存为什么最快**

管道/消息队列每次收发都要把数据从用户态拷到内核、再从内核拷到用户态（两次拷贝）。共享内存直接映射同一块物理页，进程读写就是访存，零拷贝。代价是同步逻辑要自己写。

**管道为什么是半双工**

匿名管道只有一个内核缓冲区，设计为「一端只写、一端只读」。要双向通信得建两根管道。这也是为什么 shell 的 `cmd1 | cmd2` 是单向数据流。

**signal 为什么危险**

信号处理函数在「任意时刻」打断主流程，若它调用的函数不是异步信号安全的（如 malloc、printf），可能破坏主流程的数据结构。正确做法是 signal handler 只设一个标志位，主流程轮询该标志。

## 面试常问

1. 最快的 IPC 是什么？共享内存（零拷贝），但需自己加锁同步。
2. 父子进程怎么通信？匿名管道最常见；或共享内存+信号量；或 socketpair。
3. 共享内存和消息队列怎么选？高频大块数据用共享内存（快），少量结构化消息且懒得管锁用消息队列（内核帮你同步）。
