# 中断、异常与系统调用：用户态与内核态

## 一句话结论

CPU 平时跑用户程序（用户态，权限低）；需要通过内核做的事（如读写磁盘、申请内存）要走「系统调用」，由软中断陷入内核态（权限高）执行；硬件事件（如网卡来数据）由「中断」打断当前执行去处理。两者是用户程序和内核交互的主要通道。

## 标准答案

**用户态 vs 内核态**

CPU 有特权级（如 x86 的 ring 0/3）。用户态（ring 3）不能直接访问硬件、不能执行特权指令；内核态（ring 0）可以。隔离的目的是保护操作系统不被用户程序搞崩。

**系统调用（syscall）**

用户程序主动请求内核服务的方式：`open/read/write/fork/...`。执行「陷入指令」（如 x86 的 `syscall`/`int 0x80`）从用户态切到内核态，内核查表执行对应服务，返回结果再切回。切态有开销（保存/恢复现场、上下文切换）。

**中断（interrupt）**

由硬件异步触发：键盘敲一下、网卡收到包、时钟到时。CPU 收到中断信号，暂停当前程序，跳到中断处理程序（ISR），处理完返回。分硬件中断和时钟中断（操作系统靠时钟中断做进程调度）。

**异常（exception / trap）**

由当前指令执行出错或主动触发：除零、缺页、断点。缺页异常很常见——访问还没映射进内存的虚拟地址时触发，内核把页面调进来再重试指令。

## 原理展开

**系统调用为什么会慢**

一次系统调用要：用户态→内核态切换（保存寄存器/栈）、内核执行、内核态→用户态切回。高频调用（如每条日志都 write）累积开销大，所以有了用户态缓冲（如 stdio 的 fwrite 缓冲、write 批量）来减少切态次数。

**中断和轮询的区别**

轮询是程序主动不断问「有数据吗」，简单但浪费 CPU；中断是硬件「有事叫我」，CPU 平时干别的，来了才处理，省 CPU 但响应有延迟且高频中断会打断。现代网卡用「中断+轮询」混合（NAPI）：来少量包用中断，突发流量切轮询。

**缺页异常是错误吗**

不是。它是虚拟内存机制的正常工作方式：程序访问的页面还没调入物理内存，触发缺页，内核分配物理页、从磁盘/交换区装入、建立映射，然后重新执行那条指令。只有「访问了根本不该访问的地址」才会变成真正的段错误（SIGSEGV）。

## 面试常问

1. 用户态和内核态怎么切换？系统调用（主动陷入）、中断（硬件）、异常（指令出错）三种途径，都要切特权级并保存现场。
2. 一次系统调用发生了几次上下文切换？至少两次（用户→内核、内核→用户）；若内核调度了别的进程还会更多。
3. 什么是零拷贝？传统拷文件要「磁盘→内核缓冲→用户缓冲→内核 socket 缓冲→网卡」多次拷贝和切态；零拷贝（sendfile/mmap）让数据不经用户态，减少拷贝和切态，提升 I/O 吞吐。
