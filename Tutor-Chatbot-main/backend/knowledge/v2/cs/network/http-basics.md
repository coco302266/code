# HTTP 基础：方法、状态码与缓存

## 一句话结论

HTTP 是「请求-响应」的无状态应用层协议；方法表达意图（GET 取、POST 改等），状态码表达结果（2xx 成功、3xx 重定向、4xx 客户端错、5xx 服务端错），缓存靠请求/响应头协商来减少重复传输。

## 标准答案

**常用方法**

- GET：获取资源，幂等，参数在 URL。
- POST：提交数据，非幂等，参数在 body。
- PUT：整体替换资源，幂等。
- DELETE：删除资源，幂等。
- HEAD：只拿响应头，不拿 body（探测资源是否存在/是否改过）。
- PATCH：局部修改。

**常见状态码**

- 2xx：200 OK、201 Created、204 No Content。
- 3xx：301 永久重定向、302 临时重定向、304 Not Modified（缓存命中）。
- 4xx：400 参数错误、401 未认证、403 禁止、404 不存在、405 方法不允许。
- 5xx：500 服务端内部错、502 网关错、503 不可用、504 网关超时。

**缓存机制**

- 强缓存：响应头 `Cache-Control: max-age=3600` 或 `Expires`，命中时浏览器直接用本地副本，不发请求。
- 协商缓存：请求带 `If-None-Match`（对应响应的 `ETag`）或 `If-Modified-Since`（对应 `Last-Modified`）；服务端比对，没变就回 304，浏览器用本地副本。

## 原理展开

**幂等是什么意思**

幂等 = 同一个请求执行一次和执行多次效果相同。GET/PUT/DELETE 是幂等的，POST 不是。这条性质决定了「重试是否安全」：GET 重试无所谓，POST 重试可能重复下单，所以支付类接口要用幂等键（idempotency key）兜底。

**301 和 302 对 SEO 的区别**

301 是永久迁移，搜索引擎会把权重转移到新地址；302 是临时，权重留在旧地址。用错会导致收录异常。

**Cookie 和 Session 怎么配合**

Cookie 是存在浏览器的一段数据，每次请求自动带上；Session 是服务端保存的会话状态，通常把 session id 放在 Cookie 里传给服务端。这样无状态的 HTTP 也能识别「这是同一个用户」。

## 面试常问

1. GET 和 POST 的区别？语义上 GET 取/幂等/参数在 URL、POST 改/非幂等/参数在 body；安全上 GET 参数暴露在 URL 和日志里，POST 相对不暴露（但都不加密，加密靠 HTTPS）。
2. 304 是怎么来的？协商缓存命中：请求带 ETag/Last-Modified，服务端比对发现资源没变，回 304 让浏览器用本地副本。
3. 状态码 401 和 403 区别？401 是「你没登录/没凭证」，403 是「你登录了但没有权限」。
