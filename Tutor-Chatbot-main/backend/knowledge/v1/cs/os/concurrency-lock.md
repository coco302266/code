# 并发与锁：互斥、信号量、条件变量与读写锁

## 一句话结论

并发编程的核心是「多个执行流访问共享资源时不出错」。锁（互斥量）保证同一时刻只有一个线程进临界区；信号量控制一类资源的并发数量；条件变量用于「等某个条件成立」；读写锁区分读多写少的场景。

## 标准答案

**互斥量（mutex）**

最基础的锁：`lock()` 进入临界区，`unlock()` 离开。同一时刻只有一个线程持有。忘记 unlock 会死锁；持有锁时阻塞（如等 I/O）会拖慢别人——锁的粒度要小。

**信号量（semaphore）**

一个计数器，P（wait）减 1、V（signal）加 1；减到 0 再 P 就阻塞。初始值 N 表示允许 N 个线程同时进入。可用于限流、生产者-消费者（配合两个信号量）。

**条件变量（condition variable）**

「等待某个条件成立」的机制，必须配合 mutex 使用：`wait()` 释放锁并阻塞，`signal()/broadcast()` 唤醒。典型用法是 while 循环检查条件（防虚假唤醒），不要 if。

**读写锁（rwlock）**

读锁共享（多人同时读），写锁独占。适合「读多写少」：读之间不互斥，有写者时读写都阻塞。

## 原理展开

**自旋锁 vs 互斥锁**

- 互斥锁（sleeping lock）：抢不到就休眠，让出 CPU，适合临界区较长。
- 自旋锁：抢不到就忙等（循环检测），不休眠，适合临界区极短、且不能休眠的上下文（如中断处理）。忙等浪费 CPU 但免去上下文切换开销。

**死锁怎么在代码里预防**

最常见手段是「固定加锁顺序」：所有线程按相同顺序申请多个锁，环路就构造不出来（详见死锁文档）。其次是超时退避、一次性申请全部锁。

**CAS 与无锁编程**

CAS（Compare-And-Swap）是一条原子指令：比较内存值与预期值，相等才更新。依靠它可实现无锁栈/队列，避免锁的开销和死锁，但存在 ABA 问题（值被改回原值，CAS 误以为没变），可用版本号解决。

## 面试常问

1. 用两个线程各对计数器加一亿次，不加锁结果会怎样？结果随机小于两亿，因为 `count++` 不是原子的（读-改-写三步可被打断），要用原子变量或锁。
2. 什么是惊群效应？多个线程等同一个条件变量被 broadcast 唤醒，但只有一个人能拿到资源，其余又睡回去，浪费调度。解决用精细通知或一次性只 signal 一个。
3. 什么是优先级反转？低优先级线程持有锁，高优先级线程等这把锁，但中等优先级线程抢占了低优先级导致高优先级被间接阻塞。解决用优先级继承协议。
