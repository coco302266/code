# TCP 可靠传输：确认、重传、滑动窗口与拥塞控制

## 一句话结论

TCP 靠「序列号 + 确认(ACK) + 超时重传」保证不丢不错；靠「滑动窗口」做流量控制避免压垮接收方；靠「拥塞控制」避免压垮网络。三者共同构成 TCP 的可靠传输。

## 标准答案

**可靠传输三要素**

- 序列号：每个字节编号，接收方能按序重组、识别重复。
- 确认机制：接收方回 ACK 告知「已收到到哪」。
- 重传：发送方超时没收到 ACK 就重发；还有「快速重传」——收到 3 个重复 ACK 就立即重传，不等超时。

**滑动窗口（流量控制）**

接收方在 ACK 里带「窗口大小(rwnd)」，告诉发送方「我还能收多少」。发送方据此控制发送速率，窗口为 0 时暂停发送（避免接收方缓冲区溢出）。这是端到端的流量控制。

**拥塞控制**

防止发送方发太快把网络（路由器缓存）撑爆。核心算法：

- 慢启动：初始拥塞窗口(cwnd)小，每收到一个 ACK 窗口翻倍增长，指数爬升。
- 拥塞避免：到达阈值(ssthresh)后改为每个 RTT 加 1，线性增长。
- 快重传 + 快恢复：丢包时 cwnd 减半而非归零，更平滑。

## 原理展开

**超时重传的 RTO 怎么定**

RTO（重传超时）基于实测的往返时间 RTT 平滑计算（指数加权移动平均），并留一定余量。定太短会误重传（浪费带宽），定太长丢包后恢复慢。TCP 用 RTT 的均值和方差来动态估计。

**流量控制和拥塞控制的区别**

流量控制是「接收方」限速（怕接收方处理不过来），靠 rwnd；拥塞控制是「网络」限速（怕网络拥塞），靠 cwnd。发送方实际窗口 = min(rwnd, cwnd)。这是两个不同维度，别混。

**为什么需要快速重传**

纯超时重传要等一个 RTO（可能几百毫秒到秒级）才重发，太慢。收到 3 个重复 ACK 说明后面的包可能丢了但前面的已到，立刻重传丢失包，显著降低延迟。

## 面试常问

1. TCP 怎么保证可靠？序列号+ACK+重传（超时+快速重传），再加校验和和按序交付。
2. 滑动窗口和拥塞窗口是一回事吗？不是：rwnd 是接收方给的（流量控制），cwnd 是拥塞控制算的（网络），实际发送窗口取两者最小值。
3. 什么是粘包？TCP 是字节流没有消息边界，应用层多次 send 可能一次 recv 收到，或一次 send 分两次 recv。解决靠应用层定长/分隔符/长度前缀。
