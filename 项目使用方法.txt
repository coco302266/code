================================================================
AI Classroom（AI 智能教室）项目使用方法
面向计算机八股学习的多 Agent 辅导系统 · 使用指南
================================================================

适用版本：M4 已落地（多场景 + 多 Agent + sources 落库 + 教师备课 PPT）
最后核对：2026-10-30（以真实代码为准，非旧文档）

----------------------------------------------------------------
0. 一句话结构
----------------------------------------------------------------
- 后端：Tutor-Chatbot-main/backend（FastAPI + MySQL + ChromaDB + RAG + 多 Agent）
- 前端：Tutor-Chatbot-main/frontend（Next.js + Electron 桌面客户端）
- 角色：学生 / 教师 / AI 助教；一个课堂（classroom_id）内所有人共享上下文群聊

----------------------------------------------------------------
1. 环境准备（只做一次）
----------------------------------------------------------------
【后端】
  - Python 3.11（本机用 uv 装的 cpython-3.11.16 即可；venv 在
    Tutor-Chatbot-main/backend/venv，已在 pyvenv.cfg 指向它）
  - 依赖已装进 venv，无需重装。若换机器：在 backend 目录
    `python -m venv venv` 后 `venv\Scripts\pip install -r requirements.txt`
  - 配置：复制 backend/.env.example 为 backend/.env，填好
    MySQL 账号（DB_*）和 DeepSeek key（LLM_API_KEY / LLM_BASE_URL）
    .env 已被 git 忽略，不会进仓库

【前端】
  - Node.js（含 npm）。首次需 `cd Tutor-Chatbot-main/frontend && npm install`
  - Electron 二进制偶尔不下，补一次：
    ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ ^
    node node_modules/electron/install.js

2. 启动后端（端口 8000）
----------------------------------------------------------------
⚠️ 关键坑：启动前必须清掉代理环境变量，否则 /chat 会 502。
   本机若设了 HTTP_PROXY / HTTPS_PROXY，启动前先 unset。

方式 A（推荐，自带的启动器，已避开代理和坏路径问题）：
    cd Tutor-Chatbot-main/backend
    venv\Scripts\python.exe run_server.py
方式 B（手动）：
    cd Tutor-Chatbot-main/backend
    env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy ^
        venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000
    （注意：后端不带 --reload，改代码要重启）

验证：浏览器/curl 打开 http://127.0.0.1:8000/health
   看到 {"status":"ok","provider":"openai","model":"deepseek-flash","database":"up"} 即正常。

⚠️ 端口/CORS 重要更新（2026-10-30）：本机 3000 被另一个程序占用，前端改跑 3001。
   因此后端启动时必须把 ALLOWED_ORIGINS 设为包含 http://localhost:3001，否则前端被 CORS 拦。
   临时做法（推荐，不动文件）：
       ALLOWED_ORIGINS='["http://localhost:3001"]' venv\Scripts\python.exe run_server.py
   永久做法：改 backend/.env 的 ALLOWED_ORIGINS 同上。零基础照抄见《运行教程-新手版.md》。

3. 启动前端
----------------------------------------------------------------
方式一 · 桌面客户端（演示推荐）：
    cd Tutor-Chatbot-main/frontend
    npm run client          # 自动拉起前端服务 + 打开应用窗口
    或双击 frontend/start-client.bat
    npm run client 会先探测 3000 端口，没起就自动 npm run dev，
    关窗口时连服务一起收掉。想自己控制服务加参数：npx electron . --no-spawn

方式二 · 浏览器调试（改样式更快，推荐新手）：
    cd Tutor-Chatbot-main/frontend
    npm run dev
    然后打开 http://localhost:3001   ← 注意是 3001，不是 3000
    （⚠️ 本机 3000 被另一个程序占用，前端必须用 3001；后端 ALLOWED_ORIGINS
     也要放行 http://localhost:3001，否则浏览器会被 CORS 拦。
     零基础照抄版见同目录《运行教程-新手版.md》，内含完整命令与排障。）

后端没起时前端也能打开，但顶栏状态灯是红的，聊天会失败。

4. 四个页面（从入口进，按身份走）
----------------------------------------------------------------
  /                  双方  输入昵称、选身份（学生/教师）、填课堂号
  /classrooms/       学生  “我的课堂”：本机记的最近进过的课堂 + 用课堂号进入
  /classroom/        双方  聊天室：群聊流式讲解 + 答案下方“依据” + 右侧成员/画像
  /teacher/         教师  工作台：课堂 / 备课 / 记录 三个页签

----------------------------------------------------------------
5. 群聊怎么用（核心场景）
----------------------------------------------------------------
(1) 教师建房：进 /teacher → “课堂”页签 → 建课堂时选好协作场景
    （v1 单 Agent 讲解 / group 小组协作 / debate 辩论对抗）
    → 系统自动把教师以 teacher 身份加入该课堂（少了这步备课会 403）
    → 记住返回的“课堂号”（classroom_id）
(2) 学生进入：在自己机器上打开 / 或 /classrooms/，填同一个课堂号进入
    → 所有人进入同一个 classroom_id，即进入同一间群聊
(3) 共享上下文：同一课堂里 A 问了“死锁”，B 接着问“那怎么预防”
    接得上——群聊上下文是共享的（这是产品决策；讲解深度按各自学生隔离）
(4) 多 Agent：选了 group / debate 场景时，一条回答会拆成多个气泡，
    例如 debate 会依次出现 tutor（立论）→ peer（质疑）→ examiner（追问），
    每个气泡独立落库、刷新后仍在。
(5) 画像：右侧栏实时显示每个学生的掌握度 / 薄弱点 / 学习偏好，
    聊得越多画像越准。

----------------------------------------------------------------
6. 怎么提问
----------------------------------------------------------------
- 在 /classroom/ 底部的输入框直接打字，回车或点发送即可。
- 只发三类字段：message（你说的）、classroom_id、user_id（你的身份，
  前端存在 localStorage，刷新不丢）。不要多传字段（后端 extra="forbid" 会 422）。
- 回答是流式逐字出来的；答案下方会显示“依据”（本轮引用了哪几片知识库资料）。
- 依据已落库：刷新页面后，历史消息的依据和分气泡都还在（M4 已修，旧文档说会消失已过时）。
- 纯寒暄或问到知识库没有的点时，可能没有“依据”或没有教学状态变化，属正常。

7. 生成 PPT（教师备课）
----------------------------------------------------------------
入口：/teacher → “备课”页签
  1. 先在“课堂”页签里以教师身份加入目标课堂（备课接口要校验你是该课堂教师）
  2. 在“备课”里填主题（如“死锁的四个必要条件”），点“生成大纲”
  3. 后端会先检索常驻八股知识库（结论有资料依据），返回结构化大纲 JSON
  4. 同时渲染一个 .pptx 文件，页面给出“下载 PPT”按钮
     - 桌面客户端（npm run client）：pptx 自动存到系统“下载”文件夹
     - 浏览器调试态：点“下载 PPT”走浏览器下载
  5. 若某次模型没生成出可用大纲，直接再点一次“生成”即可；
     大纲成功但 PPT 渲染失败，大纲仍可用（页面会标“PPT 渲染失败，大纲可用”）

（底层接口：POST /resources/ppt-outline，返回大纲 JSON + 文件；
 GET /resources/files/{file_name} 下载。另有 T7 个性化资源接口
 POST /resources/generate，resource_type="slides" 且 render_pptx=true 也能出 PPT。）

8. 常见排障
----------------------------------------------------------------
【/chat 返回 502 或一直转圈】
  → 多半是启动时没清代理。杀掉后端，按第 2 节“方式 B”unset 代理后重启。

【页面白屏，控制台 _next/... 404】
  → 改过前端后 out/ 哈希对不上。关客户端 → npm run build → 重开。

【Electron 一闪没 / GPU process isn't usable】
  → 虚拟机/远程桌面里 Chromium 起不来。main.js 已默认关硬件加速退回软渲染；
    真机想开硬件加速：npx electron . --enable-gpu

【报 registerSchemesAsPrivileged undefined】
  → 环境里 ELECTRON_RUN_AS_NODE=1 把 Electron 降级成纯 Node。
    干净终端里：env -u ELECTRON_RUN_AS_NODE npm run client

【前端连不上后端（顶栏红灯）】
  → 确认后端 8000 已起、/health 返回 up；浏览器用 localhost:3000 而非 127.0.0.1。
